### Ключевые фрагменты

Роутер регистрирует точные адреса из задания; chi middleware обеспечивает RequestID и восстановление после panic, локальное middleware логирует запрос:

```go
router.Use(chimiddleware.RequestID)
router.Use(chimiddleware.Recoverer)
router.Use(middleware.Logger)
router.Use(middleware.CORS)
router.Get("/api/tasks", handler.List)
router.Post("/api/tasks", handler.Create)
router.Get("/api/tasks/{id}", handler.Get)
router.Put("/api/tasks/{id}", handler.Update)
router.Delete("/api/tasks/{id}", handler.Delete)
```

Репозиторий закрывает map RWMutex и возвращает копии значений `Task`, не изменяемые указатели:

```go
r.mu.RLock()
defer r.mu.RUnlock()
item, ok := r.tasks[id]
if !ok {
    return Task{}, ErrNotFound
}
return item, nil
```

Успешный DELETE не сериализует JSON и пишет только статус:

```go
if err := h.repo.Delete(id); err != nil {
    writeError(w, http.StatusNotFound, "task not found")
    return
}
w.WriteHeader(http.StatusNoContent)
```

## Обработка ошибок и статусы

Общий helper возвращает JSON с `Content-Type: application/json; charset=utf-8` и заданным статусом. Ошибка декодирования/неверный ID/пустой после TrimSpace title дают `400`; валидный, но отсутствующий ID — `404`. Для успешного DELETE код пишет `204` без тела, что подтверждено нулевым размером файла ответа.

## Контрольные вопросы

1. **Чем `ServeMux` отличается от chi?** Стандартный `ServeMux` входит в библиотеку Go и подходит для простого сопоставления путей. Chi — сторонний маршрутизатор с параметрами пути, вложенными маршрутами и цепочками middleware; здесь `{id}` читается через `chi.URLParam`.
2. **Для чего GET, POST, PUT, PATCH и DELETE?** GET читает ресурс; POST создаёт; PUT обычно заменяет ресурс целиком; PATCH частично изменяет; DELETE удаляет. В этом API доступны GET/POST/PUT/DELETE; PATCH заданием не требуется.
3. **Что такое middleware?** Обёртка вокруг `http.Handler`, выполняющая общие действия до/после обработчика. Здесь middleware задают CORS и журналируют метод, путь, статус и длительность; chi добавляет RequestID и Recoverer.
4. **Зачем JSON-ошибки и HTTP-статусы?** Статус позволяет клиенту понять результат на уровне HTTP, а JSON с полем `error` объясняет причину машинно-читаемым способом.
5. **Чем хранение в памяти отличается от БД?** In-memory проще и не требует отдельного сервиса, но данные теряются после остановки процесса и недоступны другим экземплярам сервера. База данных обеспечивает долговременное хранение и обычно предоставляет транзакции и конкурентный доступ между процессами.
