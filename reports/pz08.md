# Практическое занятие №8 — MongoDB и CRUD заметок

## Цель и среда

Создать API заметок на Go с официальным драйвером MongoDB, коллекцией `notes`, уникальным индексом `title` и пятью операциями CRUD. Проверить MongoDB из временного Docker Compose project.

Фактическое окружение: Windows `windows/amd64`, Go `go1.27.2`, Docker Engine `29.8.2`, Docker Compose `v5.5.1`, Windows PowerShell 5.1. Использованы Go-модули `go.mongodb.org/mongo-driver v1.17.6` и `github.com/go-chi/chi/v5 v5.2.3`. Compose запускает образ `mongo:7`; точный patch-релиз сервера не выводился.

## Реализация

Модуль находится в `practices/pz08-mongo/`. `cmd/api/main.go` запускает chi и `/health`; `internal/db/mongo.go` подключается, выполняет Ping и создаёт уникальный индекс `unique_title` по `title` до старта API. `internal/notes/model.go` описывает BSON ObjectID и JSON-поля, `repo.go` содержит операции с MongoDB, `handler.go` валидирует HTTP-запросы. Для подключения, операций, индекса и отключения заданы контекстные таймауты.

POST создаёт заметку; GET списка фильтрует по буквальному фрагменту заголовка, сортирует по `createdAt` и `_id` по убыванию и принимает `limit`/`skip`; GET по ID читает заметку; PATCH изменяет только переданные поля; DELETE возвращает 204 без тела. Поисковая строка экранируется перед передачей в MongoDB regex. Ошибка уникального индекса преобразуется в 409, отсутствующий документ — в 404, ошибочный ObjectID и параметры — в 400. Неожиданные ошибки не раскрывают детали БД клиенту.

`docker-compose.yml` использует переменные окружения для временного пользователя и пароля. `run-local.ps1` из любого каталога создаёт уникальный project, свободные loopback-порты и случайные учётные данные; после проверок выполняет `docker compose down --volumes` только для собственного project и завершает только свой процесс API. Рабочий URI и пароль не записываются в файлы.

## Контрольные вопросы

1. **Чем документная модель отличается от реляционной?** MongoDB хранит BSON-документы с вложенными полями и допускает различие структуры между документами. Реляционная БД хранит строки таблиц по заданной схеме и связывает их ключами и запросами JOIN. Выбор модели зависит от структуры данных и запросов.
2. **Что такое ObjectID?** Это 12-байтовый BSON-идентификатор документа, обычно представляемый 24 шестнадцатеричными символами. API преобразует строку в `primitive.ObjectID` и отклоняет неверный формат до обращения к БД.
3. **Как реализован CRUD и операторы обновления?** Создание — `InsertOne`, чтение — `Find`/`FindOne`, обновление — `FindOneAndUpdate` с `$set` только для переданных полей, удаление — `DeleteOne`. `$set` сохраняет остальные поля документа.
4. **Зачем нужны индексы и уникальность?** Индекс ускоряет поиск по индексируемому полю ценой дополнительной работы при записи. Уникальный индекс `title` запрещает два документа с одинаковым значением; нарушение обрабатывается как HTTP 409. Буквальный фильтр `q` здесь использует regex, поэтому индекс по `title` не обещает ускорения каждого такого поиска.
5. **Зачем нужен таймаут контекста?** Он ограничивает ожидание сетевых операций, Ping, создания индекса и запросов к MongoDB. При зависшем сервисе запрос завершается ошибкой, вместо бесконечного ожидания.

## Проблемы и вывод

В обычной среде Codex доступ к Docker Engine был отклонён; реальная проверка выполнена с разрешённым локальным доступом. Первый запуск выявил, что Windows PowerShell 5.1 обрабатывает служебный stderr Docker Compose как ошибку при строгом режиме; сценарий исправлен и проверяет код выхода Docker. Второй запуск выявил передачу пустого тела при GET из-за необязательного строкового параметра PowerShell; исправлено проверкой присутствия параметра. После этого полный сценарий прошёл, а временный проект был удалён. Конкретный patch-релиз MongoDB не фиксировался.
