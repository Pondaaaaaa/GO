## Реализация

`openDB` открывает зарегистрированный драйвер `pgx`, настраивает пул `10` открытых / `5` простаивающих соединений и lifetime `30 min`, проверяет доступность через `PingContext` с таймаутом 5 секунд. При ошибке ping соединение закрывается. `main` закрывает пул при завершении.

```go
db, err := sql.Open("pgx", dsn)
if err != nil {
    return nil, fmt.Errorf("sql.Open: %w", err)
}
db.SetMaxOpenConns(10)
db.SetMaxIdleConns(5)
db.SetConnMaxLifetime(30 * time.Minute)
```

Запросы используют параметры, а не конкатенацию значений в SQL:

```go
err := r.db.QueryRowContext(ctx,
    `INSERT INTO tasks (title) VALUES ($1) RETURNING id`, title,
).Scan(&id)
```

`ListTasks` и `ListDone` читают `rows`, проверяют ошибки `Scan` и `rows.Err()`; `rows.Close()` отложен через `defer`. `FindByID` возвращает `sql.ErrNoRows` без подмены, чтобы вызывающий код мог проверить `errors.Is`.

Пакетная вставка выполняется в транзакции:

```go
tx, err := r.db.BeginTx(ctx, nil)
if err != nil {
    return fmt.Errorf("begin transaction: %w", err)
}
defer func() { _ = tx.Rollback() }()
// INSERT выполняется внутри tx; при успехе вызывается tx.Commit().
```

Для демонстрации атомарности `main` сначала вставляет временную probe-строку в транзакции, затем передаёт пустое название. Ожидается ошибка валидации и откат; код запрашивает probe по title и проверяет `sql.ErrNoRows`.

Для упрощения запуска добавлен `practices/pz05-db/run-local.ps1`. Он использует `PGUSER` или роль `postgres` по умолчанию, запрашивает только скрытый пароль, создаёт отсутствующую базу `todo` и таблицу `tasks`, задаёт `DATABASE_URL` на время запуска и после приложения выполняет проверочный `SELECT`. Секреты не выводятся и не сохраняются; временные переменные очищаются/восстанавливаются.

DOCX просит три снимка: подготовка схемы, `go run` и `psql SELECT`. Полученный один снимок достоверно показывает все три этапа в общей сессии, но это пока один файл, а не три отдельных снимка. ## Контрольные вопросы

1. **Что такое пул `*sql.DB`?** Это потокобезопасный объект Go, который управляет набором соединений, открывает их по необходимости и повторно использует. Это не одно физическое соединение.
2. **Зачем `$1`?** Это позиционный параметр PostgreSQL. Значение передаётся отдельно от SQL, что предотвращает SQL-инъекцию и корректно обрабатывает кавычки/типы.
3. **Чем различаются `Query`, `QueryRow`, `Exec`?** `Query` подходит для нуля или многих строк и возвращает `*Rows`; `QueryRow` — для одной строки, результат обычно читают через `Scan`; `Exec` выполняет запрос без набора строк, например INSERT без `RETURNING`, UPDATE или DELETE. Для INSERT с ID здесь нужен `QueryRowContext` из-за `RETURNING id`.
4. **Зачем транзакция?** Она делает пакет вставок атомарным: либо фиксируются все операции, либо откатываются вместе. Это защищает таблицу от частично записанного пакета.
5. **Почему такие настройки пула?** До 10 открытых соединений ограничивают нагрузку маленького стенда; до 5 idle оставляют часть соединений для повторного использования, не удерживая весь максимум. Lifetime 30 минут периодически обновляет долго живущие соединения. Это учебные лимиты, не результат нагрузочного теста.
