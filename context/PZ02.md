## Основная часть

- Проверь `go version` (нужен Go ≥ 1.21) и `git --version`. В PowerShell перед Go-командами выполни локальный `setup.ps1` из корня репозитория.
- Создай `cmd/myapp/main.go` с минимальным `main`, вызывающим `internal/app.Run()`, `internal/app/app.go`, `utils/logger.go`, `go.mod`, `.gitignore` и краткий README с назначением и запуском. Не создавай `pkg/`, `vendor/`, `src/` или другие папки только ради шаблона.
- `GET /` возвращает текст `Hello, Go project structure!`; `GET /ping` — JSON с `status: "ok"` и текущим временем UTC в RFC3339. Оба маршрута вызывают логирование запроса: время, удалённый адрес, метод и путь. При запуске и ошибке сервера выводятся информационный/ошибочный логи.
- По заданию порт по умолчанию `8080`. На этом компьютере он занят внешним `httpd`, поэтому допускается небольшой настраиваемый порт для локальной проверки; зафиксируй выбранный порт в README и отчёте. Не останавливай сторонний процесс.
- Запусти `go run ./cmd/myapp`, проверь `/` и `/ping` через `curl.exe -i` (в PowerShell именно `curl.exe`), убедись, что после запросов есть логи. Отформатируй код и проверь сборку; сборка отдельного `.exe` указана как опциональная.

## Мини-упражнения и баллы

- A: middleware для `X-Request-Id`: если заголовок отсутствует, сгенерировать 16 шестнадцатеричных символов; вернуть ID в ответе. Проверить обычный запрос и передачу `X-Request-Id: demo-123`.
- B (+1 балл): `utils/httpjson.go` с `WriteJSON` и `WriteErr`, маршрут `/fail` со статусом 400 и JSON `{"error":"bad_request_example"}`.
- C (+1 балл): вынести обработчик `/ping` в `internal/app/handlers/ping.go` и подключить его из `app.go`.
- Дополнительные A/B/C небольшие; по возможности выполни все, но не считай бонусы обязательными для базового результата. Настройки VS Code и `tasks.json` — опциональны.
