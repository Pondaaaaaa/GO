## Обязательные артефакты и реализация

- Структура по DOCX: `cmd/api/main.go`, `internal/db/mongo.go`, `internal/notes/model.go`, `repo.go`, `handler.go`, `go.mod`, `go.sum`, `docker-compose.yml`, `.env.example`, README. Используй официальный драйвер с путями импорта из задания (`go.mongodb.org/mongo-driver/...`) и `github.com/go-chi/chi/v5`.
- MongoDB в Docker Compose, отдельная БД `pz8`, коллекция `notes`. Не копируй учебные `root:secret` из DOCX в рабочий compose, исходники или снимки. `.env.example` содержит только плейсхолдеры. Подключение, имя БД и адрес HTTP бери из окружения; не задавай рабочий URI с паролем по умолчанию. Подключение проверь `Ping`; для операций, создания индекса и отключения клиента используй контекст с таймаутом.
- `Note`: BSON `_id` типа ObjectID, title, content, `createdAt`, `updatedAt`, корректные JSON-поля. Создай уникальный индекс по `title` перед работой API. Обрабатывай ошибку уникального индекса как `409`, отсутствие документа как `404`, неверный JSON и параметры как `400`; внутренние ошибки не возвращай сырым текстом клиенту.
- Маршруты: `POST /api/v1/notes` → `201`; `GET /api/v1/notes?q=&limit=&skip=` → список с фильтром по заголовку, сортировкой и пагинацией; `GET /api/v1/notes/{id}` → заметка; `PATCH /api/v1/notes/{id}` → частичное обновление только переданных полей; `DELETE /api/v1/notes/{id}` → `204` без тела. Добавь `/health` по образцу DOCX. Корректно обрабатывай ObjectID, пустой/неверный title, дубликат title при создании и обновлении, отрицательные/нечисловые limit/skip. Убедись, что пользовательский текст поиска не становится произвольным MongoDB-оператором или опасным регулярным выражением.
- Из DOCX обязательны обычный CRUD, фильтр, пагинация и уникальный индекс. «Звёздочки» (текстовый поиск, TTL-индекс, курсорная пагинация, aggregation) опциональны; не делай их ценой полноты обязательных пунктов.

## Локальный запуск и проверка

Подготовь один `run-local.ps1`, вызываемый из любой директории. Он должен найти Docker Compose и Go, создать **свой временный Compose project** с уникальным именем, свободными loopback-портами и временно сгенерированным паролем MongoDB, дождаться готовности БД, собрать и запустить Go API, проверить реальные HTTP-ответы всех пяти операций, фильтр/пагинацию, частичное обновление, дубликат title, `404` и `204` без тела, затем убрать только свои контейнеры/тома и сервер. Секреты не выводи, не сохраняй и очищай из окружения в `finally`. Не останавливай чужие контейнеры и не используй их данные. Скрипт должен давать понятный вывод для настоящих скриншотов. README также объясняет ручной запуск через `docker compose up -d` с безопасным заданием переменных окружения.

Проверь `go fmt ./...`, `go vet ./...`, `go test ./...`, `go build ./...`, `go mod verify` и реальный сценарий, когда Docker Engine доступен. Если Engine недоступен из среды Codex, продолжи независимые проверки и укажи точную одну команду пользователю; успешный живой запуск не выдумывай.
