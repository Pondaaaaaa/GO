## База и код

- Проверь реальные версии Go, PostgreSQL и `psql`. PostgreSQL 14+ нужен локально; предварительно пользователь сообщил об установленном PostgreSQL. Если `psql` не в `PATH`, найди установленный клиент или объясни пользователю, как открыть SQL Shell. Не выводи и не записывай пароль в отчёт, терминальные снимки или Git.
- В PostgreSQL создай БД `todo`, если её ещё нет, подключись к ней и создай таблицу `tasks(id SERIAL PRIMARY KEY, title TEXT NOT NULL, done BOOLEAN NOT NULL DEFAULT FALSE, created_at TIMESTAMPTZ NOT NULL DEFAULT NOW())`. Сделай одну учебную вставку через `psql`, затем `SELECT * FROM tasks`. Не удаляй существующие БД, таблицы или строки. Если `todo` уже содержит чужие данные, согласуй изоляцию прежде чем изменять их.
- Структура: `main.go`, `db.go`, `repository.go`, `go.mod`, `go.sum`, README; локальный `.env` допустим, но игнорируется Git. В коде не должно быть реального или примерного рабочего пароля. Обязателен `DATABASE_URL` из окружения; если его нет, выдай понятную инструкцию настройки без раскрытия значения. `.env.example` с плейсхолдерами допустим.
- `openDB`: `sql.Open("pgx", dsn)`, `PingContext` с таймаутом, пул `SetMaxOpenConns(10)`, `SetMaxIdleConns(5)`, `SetConnMaxLifetime(30 * time.Minute)`, закрытие `db` при ошибке Ping и в конце программы. Для запросов — `context.WithTimeout` и проверка ошибок.
- `Task` отражает четыре столбца. `CreateTask` — параметризованный `INSERT ... VALUES ($1) RETURNING id` через `QueryRowContext`. `ListTasks` — `SELECT id,title,done,created_at ... ORDER BY id`, `rows.Close`, `rows.Err` и `Scan`. `main` вставляет несколько задач, печатает их ID и список, затем тот же результат проверяется в `psql`.

## Проверочные задания из DOCX

- `ListDone(ctx, done bool)` с `WHERE done = $1`; проверь оба значения. `FindByID(ctx, id int)` и вывод найденной задачи в `main`; корректно обрабатывай отсутствие строки (`sql.ErrNoRows`). `CreateMany(ctx, titles []string) error` выполняет массовую вставку в транзакции, с `Commit` при успехе и `Rollback` при ошибке. Проверь успешную вставку и атомарность при ошибке без повреждения чужих данных.
- Измерь реальные показатели пула через `db.Stats()` при локальном запуске и объясни выбор лимитов 10/5/30 минут для этого маленького стенда. Не придумывай замеры и не представляй их как нагрузочный тест.
- `go fmt ./...`, `go vet ./...`, `go test ./...`, `go build ./...`, реальный `go run .` и `SELECT * FROM tasks` в `psql`. Проверяй параметризацию и отсутствие секретов в отслеживаемых файлах.
