# Практика 3 — HTTP-сервер на `net/http`

Первоисточник: `D:\MAG\GO\Текущий контроль\Практическое занятие №3.docx`; при расхождении приоритет у DOCX. Создай отдельный модуль `practices/pz03-http/` с путём `github.com/Pondaaaaaa/GO/practices/pz03-http`. Не меняй PZ01/PZ02 и не создавай вложенный `.git`.

## Обязательная часть

- Структура: `cmd/server/main.go`, `internal/api/handlers.go`, `internal/api/middleware.go`, `internal/api/responses.go`, `internal/storage/memory.go`, `go.mod`, README и `requests.md`. Только стандартная библиотека Go, `http.ServeMux`, `http.Handler`/`HandlerFunc`; сторонний веб-фреймворк не нужен.
- In-memory модель `Task`: `id` (`int64`), `title` (`string`), `done` (`bool`). Хранилище с `sync.RWMutex`, уникальными возрастающими ID, методами создания, получения и списка.
- `GET /health`: `200` и JSON `{"status":"ok"}`. `GET /tasks`: JSON-список, `?q=` фильтрует по подстроке заголовка без учёта регистра. `POST /tasks`: принимает JSON `{"title":"..."}`, обрезает пробелы, возвращает `201` и созданную задачу. `GET /tasks/{id}`: `200` и задача либо корректная ошибка.
- Общий helper для JSON-ответов и ошибок с правильными `Content-Type` и статусами. Неправильный JSON, пустой title и неверный `Content-Type` должны давать `400`; неверный числовой ID — `400`; отсутствующий ID — `404`. Не повторяй ошибку из примера DOCX: `errors.Is(err, errors.New("not found"))` всегда сравнивает разные экземпляры ошибок. Используй sentinel-ошибку либо иной корректный способ распознать отсутствие записи.
- Middleware логирует метод, путь, фактический статус ответа и длительность запроса; не дублируй логирование в каждом обработчике. Корректно учитывай ответ без явного `WriteHeader`.
- Файл `requests.md`: **6–8 воспроизводимых `curl.exe` запросов** с ожидаемыми статусами; включи создание, список, фильтр, получение по ID и ошибки. Для PowerShell используй `curl.exe`, не алиас `curl`; после создания используй полученный ID. README объясняет запуск и проверку.

## Домашнее задание из DOCX

- Порт из переменной окружения `PORT`, по умолчанию `8080`. На этой машине `8080` занят внешним `httpd`; для фактической проверки выбери свободный порт (например, `18083`) без остановки постороннего процесса.
- Добавь Makefile **или** PowerShell-скрипт с командами `run`, `build`, `test`; для Windows достаточно PowerShell-скрипта.
- Покрой 1–2 обработчика осмысленными тестами через `httptest.NewRecorder`, включая проверку важных статусов/JSON; отдельно проверь ошибку `404` для отсутствующей задачи.

## Проверки и отчёт

Запусти `go fmt ./...`, `go vet ./...`, `go test ./...`, `go build ./...`; подними сервер через `go run ./cmd/server` и проверь маршруты командами из `requests.md`. Покажи реальные ответы, включая JSON-заголовки, статусы `200/201/400/404`, фильтр и строки middleware-логов. Отчёт `reports/pz03.md` по `context/REPORTS.md`: структура, команды и фактические результаты, обработанные ошибки, вывод, ссылка на код. DOCX №3 не требует скриншотов; не добавляй их как обязательное условие.

Дополнительные задания «по желанию/звёздочка» — PATCH, DELETE, CORS, ограничение title 3–140 с `422`, graceful shutdown. Они не нужны для базовой сдачи; выполняй только если основные требования уже завершены и проверены. Цель занятия упоминает form-data, но обязательные маршруты работают с JSON; отдельный form-data endpoint в задании не указан.
