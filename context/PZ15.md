# Практика №15 — unit-тестирование Go (testing, testify)

Источник: `D:\MAG\GO\Текущий контроль\Практическое занятие №15.docx`. Создать самостоятельный модуль `practices/pz15-tests/`; предыдущие практики не менять. Для выполнения не нужны PostgreSQL, Docker и HTTP-сервер. Следовать `AGENTS.md` и `context/REPORTS.md`.

## Обязательная реализация

- `internal/mathx`: `Sum(a,b int) int`, `Divide(a,b int) (int,error)` с ошибкой при делении на ноль. В `mathx_test.go` — `TestSum_Table` с отрицательными числами и нулём, `TestDivide_OkAndError` с нормальным делением и ошибкой. Показать стандартный `testing` и `testify/assert`, `require`.
- `internal/stringsx`: `Clip(s string,max int) string`, отрицательный `max` считать нулём; если длина не больше `max`, вернуть исходную строку, иначе срез первых `max` байт. Для этого занятия допустимо не обрабатывать границы UTF-8; явно назвать это ограничение. `TestClip` с `t.Run`: пустая строка, 0, отрицательный `max`, `max == len(s)`, `max > len(s)` и обрезка.
- `internal/service`: `User{ID int64, Email string}`, `ErrNotFound`, интерфейс `UserRepo.ByEmail(email)`, `Service.FindIDByEmail(email) (int64,error)`. В тесте использовать локальный stub или mock репозитория без БД; проверить найденный ID и `assert.ErrorIs(err, ErrNotFound)` для отсутствующего пользователя. Проверить возврат ошибки репозитория, если добавлен такой сценарий.
- Понятный `README.md` с командами воспроизведения. Зависимость `testify` закрепить в `go.mod`/`go.sum`.

## Проверка и сдача

Выполнить фактически: `go test ./...`, `go test -v ./internal/...`, `go test -cover ./...`, `go test -coverprofile=coverage.out ./...`, `go tool cover -html=coverage.out` (допустим `-o` для сохранения HTML). В каждом из пакетов `mathx`, `stringsx`, `service` требуется покрытие **не ниже 70%**; показать отдельные фактические проценты. Логи сохранить в `reports/logs/pz15/`; HTML-отчёт при сохранении можно поместить туда же и связать с Markdown. Настоящий скриншот HTML при наличии, но он необязателен. Проверить `go fmt`, `go vet`, сборку и `go mod verify` как дополнительные проверки проекта.

Создать `reports/pz15.md` и `reports/word/pz15.docx`: ссылка на репозиторий и код, структура, команды и подлинные результаты `go test`/покрытия, что протестировано, ограничение `Clip`, 3–5 предложений итоговых выводов, ответы на **6 контрольных вопросов** исходного DOCX. Word генерировать из окончательного Markdown через `scripts/export_reports_docx.py` и сверить содержимое. Не выдумывать результаты и скриншоты; не включать ФИО, группу, пароли или другие личные данные.

Бонусы со звёздочкой — `BenchmarkSum` и тест паники — **необязательны**. Если сделан бенчмарк, не допустить удаления вычисления оптимизатором, показать реальный запуск и осторожную интерпретацию. GitHub Actions упомянуты в теории, но отдельный workflow не требуется. Подготовить локальный коммит, push и PR выполняет пользователь.
