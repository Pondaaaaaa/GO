# Практика 1 — установка окружения Go и минимальный HTTP-сервис

Первоисточник: `D:\MAG\GO\Текущий контроль\Практическое занятие №1.docx`.

## Обязательный результат

- Проверить версии Go и Git.
- Создать отдельный модуль Go с `go.mod`, точкой входа `cmd/server/main.go` и README.
- Сервер на стандартном `net/http`: `GET /hello` возвращает статус 200 и текст `Hello, world!`; `GET /user` возвращает статус 200, `Content-Type: application/json` и JSON с `id` в формате нового UUID и `name: Gopher`.
- Подключить и действительно использовать `github.com/google/uuid`; сохранить зависимость в `go.mod` и `go.sum`.
- Проверить оба маршрута через `curl.exe`, запустить через `go run ./cmd/server`, собрать `.exe` через `go build` и проверить запуск бинарника.
- Выполнить `go fmt ./...` и `go vet ./...` без ошибок.
- README: описание, требования, запуск/сборка, примеры запросов, структура файлов, конфигурация (если она есть).
- Разместить код в GitHub-репозитории `Pondaaaaaa/GO`. Отчёт должен содержать ссылку на код и настоящие скриншоты `go version`, ответов `/hello` и `/user`.

## Критерии приёмки из задания

Репозиторий клонируется; `go build` проходит; запуск из исходников и `.exe` работает; оба маршрута отвечают 200; UUID реально генерируется; README воспроизводим; код отформатирован и `go vet` чистый.

## Дополнительное, не обязательное

Порт через `APP_PORT`, маршрут `/health` со временем RFC3339, базовое логирование запросов. Делать только после обязательной части и если это не затягивает работу. Не выдавать бонусные пункты за обязательные.

## Особенности Windows

В PowerShell используй `curl.exe`, чтобы не спутать его с PowerShell-алиасом. Локальный Go подключается через `setup.ps1` в корне репозитория. При занятом порте корректно завершай свой сервер перед повторным запуском.
