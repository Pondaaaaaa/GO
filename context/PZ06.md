# Практика 6 — GORM, миграции и связи

Первоисточник: `D:\MAG\GO\Текущий контроль\Практическое занятие №6.docx`; при расхождении приоритет у DOCX. Отдельный модуль `practices/pz06-gorm/` с путём `github.com/Pondaaaaaa/GO/practices/pz06-gorm`. Используй `gorm.io/gorm`, `gorm.io/driver/postgres` и `github.com/go-chi/chi/v5`. PZ05 и её БД `todo` не изменяй. Правила автоматизации — `context/AUTOMATION.md`.

## Обязательная реализация

- Структура из DOCX: `cmd/server/main.go`, `internal/db/postgres.go`, `internal/models/models.go`, `internal/http/router.go`, `internal/http/handlers.go`, `go.mod`, `go.sum`, README. Внешний путь `internal/http`, имя пакета может быть `httpapi`.
- Отдельная БД `pz6_gorm`. Подключение через временную `DB_DSN`; не используй пример DOCX с `setx` и паролем в командной строке. Настрой пул `20` открытых, `10` idle, lifetime `1h` через `db.DB()`. Закрой соединения при завершении. Выполни `AutoMigrate` для `User`, `Note`, `Tag` перед запуском HTTP-сервера. Проверь создание таблиц `users`, `notes`, `tags`, `note_tags` и ключей. Не применяй миграцию к чужой схеме без проверки.
- `User`: ID, Name, уникальный Email, `Notes []Note` (1:N), timestamps. `Note`: ID, Title, Content, UserID/User, `Tags []Tag` с `gorm:"many2many:note_tags;"`, timestamps. `Tag`: ID, уникальный Name, обратная связь Notes, timestamps. Избегай циклов и лишних связанных полей в JSON-ответах; можно использовать DTO.
- HTTP: `GET /health` → `200` JSON `{"status":"ok"}`; `POST /users` → `201` с пользователем; `POST /notes` принимает title/content/userId/имена тегов, создаёт заметку и связи; `GET /notes/{id}` возвращает заметку с загруженными `User` и `Tags` через `Preload`. Проверяй JSON, обязательные поля и ID. Ошибки `400`, `404`, `409` и `500` различай; дубликат email обрабатывай как `409`, ранее созданный тег переиспользуй, не отдавай сырой текст ошибки БД. Не игнорируй ошибку создания тега; связанное создание сделай атомарным там, где нужно.
- Проверяй связь 1:N (пользователь → заметки) и M:N (заметка ↔ теги) фактическими ответами и структурой таблиц. В примере DOCX есть `chi`-роутер; стандартный `net/http` используется для сервера.

При необходимости сверяй детали по официальной документации GORM: [миграции](https://gorm.io/docs/migration.html), [many-to-many](https://gorm.io/docs/many_to_many.html), [Preload](https://gorm.io/docs/preload.html), [обработка ошибок](https://gorm.io/docs/error_handling.html). Для распознавания уникального конфликта можно включить `TranslateError` и проверять `gorm.ErrDuplicatedKey`.

## Один запуск и проверка

Добавь `run-local.ps1` по `context/AUTOMATION.md`: из любой директории пользователь запускает одну команду и вводит только пароль PostgreSQL скрытым вводом. Скрипт находит `psql` (локально в №5 был `D:\programDev\bin\psql.exe`), создаёт `pz6_gorm` при отсутствии, подготавливает Go, временно задаёт DSN, запускает миграцию/сервер на свободном порту вместо занятого `8080`, автоматически выполняет запросы `/health`, создание пользователя, заметки с двумя тегами и получение заметки, затем показывает схему в `psql`. ID бери из фактических ответов, не считай его равным 1. После проверки останови только свой сервер и очисти секреты. Уникальный email для каждого запуска делает сценарий повторяемым.

Проверь `go fmt ./...`, `go vet ./...`, `go test ./...`, `go build ./...` и реальные HTTP-ответы/таблицы. Если захват окна недоступен, автоматический текстовый вывод всё равно должен быть пригоден для настоящих пользовательских снимков.
