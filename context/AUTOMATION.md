# Автоматизация локальных практик

Используй этот файл только для практик с PostgreSQL, Docker или другим локальным сервисом. По предпочтению пользователя подготовь в модуле один `run-local.ps1`, запускаемый одной командой из любого каталога. Скрипт должен выполнять доступные этапы задания сам: найти инструменты, подключить локальный Go, подготовить отдельную учебную БД/схему, запустить приложение, дождаться готовности, выполнить реальные проверки и показать понятный результат. README объясняет одну команду запуска и только необходимые настройки.

- Для PostgreSQL запроси пароль один раз через `Read-Host -AsSecureString`; по умолчанию роль `postgres`, при необходимости допускай `PGUSER`. Не выводи пароль, URL подключения и переменные с секретами; не применяй `setx`, не записывай секреты в Git, отчёт, лог или снимки. Временные `PGPASSWORD`/`DB_DSN`/`DATABASE_URL` восстанавливай или удаляй в `finally`.
- Повторный запуск должен быть безопасен: `CREATE DATABASE` только если БД отсутствует, миграция без `DROP`/`TRUNCATE`, тестовые имена и email уникальны. Не меняй неизвестные пользовательские данные и не останавливай чужой процесс, занимающий порт. Используй отдельную БД на практику и свободный порт.
- В автоматической проверке используй таймауты и проверяй коды завершения и HTTP-статусы: `$LASTEXITCODE` относится к нативным программам, ошибки PowerShell-скриптов проверяй отдельно. Запущенный скриптом фоновый сервер заверши сам, включая путь ошибки. Вывод должен быть читаемым в Windows PowerShell, включая кириллицу. Настоящие скриншоты пользователь может снять с этого вывода; не генерируй имитацию терминала.
- Автоматизация не должна скрывать невыполненные пункты: в отчёт вноси только фактические результаты. Если пароль или доступ к сервису отсутствует, подготовь остальное и назови конкретный блокер.
